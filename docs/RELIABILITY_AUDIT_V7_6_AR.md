# Masr Guide AI v7.6 — مراجعة استباقية للاعتمادية والأمان

**تاريخ المراجعة:** 15 أكتوبر 2026

## القرار

هذه نسخة كود **Portfolio Candidate / Development** وليست اعتمادًا للإنتاج التجاري أو خدمة يمكن الاعتماد عليها في الحجوزات والطوارئ. لا يمكن إثبات عدم وجود أخطاء مستقبلية أو الادعاء باختبار جميع سيناريوهات العالم الحقيقي.

## ما تم فحصه

- مراجعة للـ API والمصادقة وحفظ الرحلات والمحادثات وروابط الشركاء والـ RAG/Gemini والحدود الأمنية وملفات النشر.
- تشغيل الاختبارات الحالية والاختبارات الهجومية الجديدة من حزمة نظيفة، والـ QA المحلية، واختبار الضغط على المخطط.
- اختبار HTTP body-stream يتعمد تزوير `Content-Length`، وتخطي حد الحجم على دفعات متعددة.
- اختبار حفظ بيانات رحلات مشوهة يمكن أن تسقط الواجهة، وعمليات حفظ معتمدة على نسخ التحديث.
- اختبار حذف حساب وفحص إبطال كل الجلسات وحذف الرحلات والمحادثات المرتبطة به.
- فحص سليم لمحتويات ZIP وعدم وجود `.env` أو ملفات DB الفعلية ومفاتيح Google/OpenAI بنمط معروف.

## الإصلاحات المطبقة في الإصدار

1. **حجم الطلب الحقيقي:** طبقة ASGI تقرأ حجم جسم طلب الـAPI حتى حد 512KB. الطلبات المتدفقة أو ذات Content-Length مضلل تُرفض بـ413 **قبل** JSON parsing.
2. **سلامة بيانات الرحلات:** رفض أي `stop` غير منظم، أو لا يحتوي `place.id` و`place.name` صحيحين، بدل حفظه ليؤدي إلى انهيار React عند العرض.
3. **الكتابة المتعارضة:** عند `APP_ENV=production` (أو `REQUIRE_CONDITIONAL_WRITES=true`) يتم إلزام `If-Match` عند تحديث رحلة محفوظة أو محادثة. عدم إرساله يعيد 428؛ النسخ القديمة تعيد 409، مع الاحتفاظ بالبيانات الأصلية.
4. **الخصوصية:** `DELETE /api/my/account` يشترط كلمة المرور وتأكيدًا صريحًا، ويحذف الحساب ورحلاته ومحادثاته وجلساته؛ أضيفت الواجهة اللازمة. ملاحظة: طلبات الشركاء سجلات تجارية منفصلة وليست مرتبطة بحساب المستخدم تلقائيًا.
5. **اتصالات SQLite:** أصبح فتح اتصالات قاعدة الحسابات يستخدم Context Manager يضمن `commit/rollback` و`close` حتى عند الاستثناء، مع إغلاق اتصال قراءة جاهزية الكتالوج.
6. **المصادقة:** رفض عناوين بريد تحتوي تحكمًا أو مسافات أو بنية خاطئة بدل قبولها كمفاتيح حسابات مربكة.
7. **Readiness مقابل Liveness:** `/api/ready` يفحص جداول بيانات الحسابات والمحتوى والمعالم؛ `/api/health` يبقى فحص استجابة التطبيق. أصبحت Docker وRender تستخدم readiness في الفحص الصحي.
8. **حماية نشر الإنتاج:** لو `APP_ENV=production` يحتاج المشغّل تأكيدًا صريحًا `MASR_DURABLE_STORAGE_CONFIRMED=yes` حتى لا يستخدم تخزينًا مؤقتًا من غير إقرار بخطره؛ **هذا لا يثبت وحده وجود قرص دائم أو نسخ احتياطية**. ملف Render المجاني مضبوط على `APP_ENV=portfolio` وتخزينه مؤقت.
9. **تغطية اختبارات إضافية:** فحوص ASGI، تزوير أحجام الطلبات، صلاحيات البيانات، تحديثات قديمة، حذف الحساب، وبيانات مستوردة تالفة.

- **21/21** فحص HTTP حي محلي ضد FastAPI وخادم OpenAI وهمي/محاكى، دون أي استدعاء فعلي لخدمة Gemini أو OpenAI.
- **52/52** معايير Chatbot المصححة، مقابل **50/52** في المعيار الأصلي (شرطان متناقضان مع التعديل الناجح).

- **18,000** فحص اتساق لبرامج السفر عبر 1,500 حالة.

- `pip check` في بيئة الأدوات يشير إلى تعارض Pillow الخاص بـmoviepy عالميًا؛ غير مرتبط بمتطلبات Backend المذكورة في المشروع ولا يثبت عيبًا في المشروع.

## اختبارات إضافية **مطلوبة قبل إطلاق تجاري**

- React: `npm ci && npm run lint && npm test && npm run build`، وPlaywright/متصفح حقيقي على Chrome/Firefox/Mobile. لم تتوفر مكتبات npm المكتملة في بيئة المراجعة.
- اختبار Gemini الحقيقي بمفتاح سري **جديد** لم يُشارك في المحادثات، بما فيه انقطاع الخدمة والـquota والمحادثات المتتابعة والتكاليف.
- PostgreSQL أو قاعدة مستقرة أخرى واستراتيجية نسخ احتياطية مجربة: SQLite المحلي على خدمة مجانية قد يضيع عند restart أو redeploy.
- Rate limiting موزّع عبر Proxy/API Gateway؛ المحددات الحالية في ذاكرة العملية فقط ولا تكفي لحماية عدة عُقد أو إساءة استخدام من عدة IPs.
- اختبارات ثغرات وتبعيات محدثة (Python وnpm) مع أدوات فحص خاصة، ومراجعة مستقلة، واختبار الضغط مع مستخدمين متزامنين.
- إعداد Proxy وHTTPS وSecrets Manager وCORS وسياسة خصوصية وحذف بيانات السائح، ومراقبة أخطاء وتكاليف وإشعارات أعطال.
- التعاقد مع شركاء سياحيين والتحقق من الحجوزات فعليًا؛ نقرات الإحالة ليست حجوزات ولا أرباحًا مؤكدة.
- التحقق الدوري من بيانات السياحة والأسعار والمواصلات والفتح والإغلاق من المصادر الأصلية. لا تعتمد على الردود كإرشاد للطوارئ.

## إعدادات التشغيل والنشر

- تطوير محلي: `APP_ENV` غير معيّن، وتحديثات قديمة دون If-Match متاحة للتوافق مع المشاريع السابقة.
- عرض HR محدود: `APP_ENV=portfolio`، تحذير واضح أن البيانات قد تُمحى عند إعادة تشغيل الاستضافة المجانية. لا تستخدم معلومات حقيقية حساسة.
- **إنتاج فعلي:** `APP_ENV=production`, `MASR_DURABLE_STORAGE_CONFIRMED=yes` بعد تحقق بشري من تخزين دائم واسترجاع النسخ الاحتياطية، و`If-Match` إجباري للتحديث. لا تفعّل هذا الوضع على استضافة مؤقتة.
- مفاتيح Gemini وAdmin توضع في إعدادات الاستضافة السرية فقط، لا تُضاف إلى GitHub ولا إلى واجهة React.
