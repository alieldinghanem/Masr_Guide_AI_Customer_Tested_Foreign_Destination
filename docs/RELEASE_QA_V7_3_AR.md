# Masr Guide AI v7.3 — تقرير QA وتسليم الكود

التاريخ: 15 أكتوبر 2026. الحالة: **Portfolio Release Candidate / غير معتمد كإنتاج تجاري**.

## النتائج التي تم تنفيذها

- فحص أصل الإصدار: ZIP v7.2 سليم، والعمل بدأ من الملفات نفسها.
- **126/126** اختبار Backend / FastAPI نجح، بما في ذلك **8 حالات انحدار جديدة**.
- **67** سيناريو محادثة عبر TestClient في وضع محلي بلا Gemini.
- **52/52** في معايير قبول مصححة منطقيًا مع الحفاظ على نفس سياق الحالات.
- **50/52** في المعايير الأصلية غير المعدّلة، مع إخفاقين معروفين بسبب توقعات غير صحيحة.
- تم اختبار أن الـQA المصحح يُرجع exit status = 1 إذا فشل معيار فعلي، فيتوقف GitHub CI بدل الاكتفاء بطباعة PASS/FAIL.
- فحص Parsing لـ 29 ملف JavaScript/JSX بواسطة TypeScript transpiler: بدون أخطاء صياغة.
- تحميل GitHub Actions YAML بنجاح، وسلامة ملف ZIP وفحص الأسرار عند التسليم.

## لماذا يظل الاختبار الأصلي 50/52؟

**Q49** يبحث عن `Hurghada` داخل وجهات الرحلة *بعد* تنفيذ `Replace Hurghada with Sharm El Sheikh`؛ السلوك المطلوب الصحيح هو إزالتها من الوجهات النهائية. **Q52** يبحث عن `could not identify` رغم نجاح التعديل؛ السلوك الصحيح تأكيد التنفيذ وليس إعلان فشل غير حقيقي. لا ينبغي تخريب الـTrip State أو صياغة الرد فقط لرفع عدد الاختبارات.

الملف `qa_chatbot/legacy_acceptance_v7.py` موجود كما كان بدون تعديل. يوجد `qa_chatbot/corrected_acceptance_results_v73.json` والنتائج الأصلية في `qa_chatbot/legacy_acceptance_results_v73.json` للتحقق من الفرق.

## تحسينات الكود في v7.3

- تغيير عدد أيام المدينة/البحر بعد إنشاء الرحلة، بدون تغيير إجمالي الأيام خطأً.
- احترام توزيع أيام صريح مثل 13 يوم القاهرة و7 البحر عند تعديل رحلة موجودة.
- السماح بتعديل إجمالي الرحلة وأيام البحر في رسالة واحدة حتى عند ذكر أيام البحر أولًا.
- إضافة تفضيلات السفر العائلي عند ذكر أطفال في رسالة متابعة.
- رفض تقسيم يناقض مدة رحلة صريحة بدل اختلاق تخصيص أيام.
- توحيد رقم الإصدار المعروض في API والواجهة، وتحديث CI ليشغّل نسختي الـQA بصورة شفافة ويوقف النشر عند فشل المعيار الصحيح.
- تحسين وصف المواقع في الرد الإنجليزي من «verified» إلى «curated» لتجنب المبالغة في التحقق.

## قيود واضحة وأعمال متبقية قبل الإطلاق

1. `frontend`: يجب نجاح `npm ci && npm test && npm run build && npm run lint` في جهاز متصل أو GitHub Actions، ثم اختبار Desktop/Mobile فعليًا. انقطاع DNS مع npm registry حال دون إثبات البناء هنا.
2. **Gemini الحي**: يحتاج مفتاحًا جديدًا مؤمّنًا واختبار جودة حوارات طويلة ودقة المصادر وPrompt Injection.
3. **الأمان**: مراجعة واعتماد Security/Privacy، وضبط حدود الطلبات وقاعدة بيانات دائمة ونسخ احتياطية قبل فتح تسجيل مستخدمين حقيقيين.
4. **التجارة**: العروض روابط إحالة فقط. لا يوجد تأكيد حجز أو عمولة أو مدفوعات. تتطلب شركاء رسميين وعقودًا قبل الإعلان عن ربح حقيقي.
5. **المحتوى**: الصور وبيانات الوجهات والساعات والأسعار تحتاج فحص جودة وتحديث وترخيص قبل الإطلاق التجاري.
