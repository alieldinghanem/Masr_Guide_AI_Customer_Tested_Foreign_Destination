# ما الذي ينقص قبل إطلاق شركة سياحية تجارية فعلية؟

هذا الإصدار **Portfolio/Advanced MVP** وليس منصة حجز مرخصة أو خدمة إنتاجية بمعايير مالية وتنظيمية مكتملة.

## مكتمل برمجيًا في الإصدار الخامس

- واجهة React للتسويق لمصر والاكتشاف، صفحات تجارب ومقالات سياحية.
- API لقاعدة المعالم وPlanner ومساعد Gemini اختياري.
- حسابات سياح وجلسات وتخزين رحلات بخاصية العزل.
- CMS للمحتوى مع مسودات/نشر محميّة بكود Staff منفصل.
- مراجعة الشركاء والروابط الخارجية والتتبع المحدود للنقرات.
- Budget Calculator يعتمد على الأرقام التي يدخلها المسافر، دون اختراع أسعار سوق.
- Docker أحادي المنشأ، Compose محلي بقاعدة SQLite محفوظة في Volume، Render preview، CI GitHub.

## غير مكتمل تجاريًا — لا تدّعي تشغيله

1. **الحجوزات والفنادق:** لا يوجد Live Inventory أو دفع أو تأكيد أو تذاكر أو تكامل رسمي مع شركاء.
2. **الإيرادات:** Click Tracking ليس دليل حجز أو عمولة مستحقة؛ لا يوجد Payout Ledger.
3. **التخزين السحابي:** SQLite مطلوب له Persistent Disk + Backups، أو Backend يدعم PostgreSQL مُدار للإنتاج.
4. **أمان الحسابات:** يحتاج Email Verification، Reset Password، Rate Limiting مُوزّع، Auth Hardening، Monitoring، Audit، حماية من Abuse، واختبار اختراق مستقل.
5. **البيانات والمحتوى:** زيادة الأماكن، صور مرخصة، مصادر متحققة، مراجعة دقة وساعات العمل والأنشطة والأسعار.
6. **عمق الـAI:** تقييمات متعددة اللغات، ذاكرة دائمة بموافقة المستخدم، استرجاع حديث بمصادر، تقييم جودة التخطيط ومراقبة التكلفة.
7. **القانون:** تسجيل تجاري مناسب، شروط استخدام وخصوصية، وإحالات/حجوزات عبر شركاء مرخصين وبعد مراجعة محامٍ.
8. **الجاهزية التقنية:** نجاح CI للـFrontend على GitHub، اختبار E2E عبر متصفح فعلي، فحص الصور على الأجهزة، مراقبة التوافر والاستعادة من النسخ الاحتياطية.
9. **التشغيل التجاري:** CRM وPartner Contracts وDispute Workflow وRefund/Reconciliation عند إضافة حجوزات حقيقية.

## إرشاد العرض المهني

النسخة **ممتازة كنطاق عملي لمهارات Full-Stack + Applied AI** إذا نجح Build/UI في بيئتك وربطتها برابط Live؛ لكنها ليست إثبات نجاح تجاري أو تشغيل حجوزات حقيقية. لا تكتب في CV أنك حققت Revenue أو Integration مع Viator/Booking.com ما لم يتحقق ذلك فعلًا.
