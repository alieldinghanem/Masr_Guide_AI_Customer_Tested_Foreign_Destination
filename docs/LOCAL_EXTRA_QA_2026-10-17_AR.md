# Masr Guide AI — تقرير اختبارات غير تقليدية (Local Black-Box QA)

**التاريخ:** 17 أكتوبر 2026  
**النسخة المرجعية:** آخر سورس كامل من محادثة Masr Guide AI  
**النطاق:** خادم FastAPI محلي يعمل على منفذ عشوائي، بيانات SQLite مؤقتة، لا اتصالات AI حقيقية ولا بيانات شخصية فعلية.

## المجموعات الإضافية

| النوع | ما تم تنفيذه فعليًا |
|---|---|
| Authorization / IDOR | إنشاء حسابين منفصلين؛ رفض عرض وتعديل وحذف رحلة المستخدم الآخر؛ منع الوصول إلى تصدير الحساب أو إدارة المحتوى دون صلاحية |
| Concurrency | **10** عمليات تعديل متزامنة لنفس الرحلة وبنفس `If-Match`؛ تحديث واحد نجح و9 تعارضات `409`، دون نسخ مكررة |
| Malformed / oversized input | JSON غير صالح، طلب HTTP أكبر من 512 KiB بطريقتين، **8** طلبات تخطيط غير صالحة، ومدة انتقال سالبة |
| Rate limiting / IP spoofing | **7** محاولات دخول فاشلة مع تبديل `X-Forwarded-For` و`X-Real-IP`؛ تفعيل المنع بعد أول 5 محاولات بالضبط |
| HTTP browser defenses | `no-store` للمحتوى الحساس، `nosniff` و`X-Frame-Options` وفحص CORS |
| Partners | رفض **4** روابط وجهات شريكة خطرة أو غير معتمدة وفق سياسة التطبيق |
| Randomized property testing | **90** رحلة عشوائية ذات قيود مختلفة؛ فحص عدد الأيام، ترتيب الأيام، عدم تكرار المعالم وتخصيص المدن |
| Local load | **140** طلب HTTP باستخدام **16** worker؛ جميعها أعادت 200 |
| Account lifecycle | انتهاء صلاحية التوكن بعد الخروج، إلغاء التوكن بعد الحذف، والتحقق الفعلي من حذف رحلات الحساب في DB |
| Restart recovery | إيقاف خادم Uvicorn وإعادة تشغيله في عملية جديدة؛ استرجاع حساب ورحلة محفوظة من قاعدة SQLite مؤقتة |
| Release configuration | فحص إعدادات Docker وWindows والتأكد من تعطيل الثقة الضمنية بهيدرز Proxy |

**قياسات آخر جولة للضغط المحلي:** p50 = 59.44 ms، p95 = 101.27 ms، والحد الأقصى = 122.92 ms. هذه أرقام خاصة بالبيئة الحالية ولا تدل على SLA أو تحمّل أعداد مستخدمين في الإنترنت.

## المشكلة التي كشفتها هذه الاختبارات وتم علاجها

في التجربة الأولى، ظهر **31 نجاحًا و1 فشلًا**: رغم أن كود Rate Limiting يعتمد على عنوان اتصال العميل، فإن Uvicorn قد يغيّر `request.client.host` اعتمادًا على هيدرز Proxy موثوقة افتراضيًا عند ورود الطلب من `127.0.0.1`. أمكن في هذه الحالة تبديل عنوان IP الظاهر بين المحاولات، فلم يُفعَّل الحد المطلوب.

**الإصلاح المطبق:** إضافة `--no-proxy-headers` صراحةً إلى أوامر تشغيل Uvicorn في:

- `Dockerfile`
- `backend/Dockerfile`
- `RUN_BACKEND_WINDOWS.bat`
- `scripts/open_local_website.py`
- `scripts/open_quick_demo.py`

ثم أُعيد الاختبار فنجح، مع إضافة فحص يضمن عدم إزالة هذا الإعداد من أوامر التشغيل. الثغرة التي أُعيد إنتاجها تعتمد على ظروف الشبكة/البروكسي، ولا تثبت وحدها إمكان استغلال تطبيق منشور؛ النشر خلف Reverse Proxy يحتاج إعداد ثقة مدروسًا وRate Limiting عند الحافة.

## غير منفذ أو غير متحقق بهذا الاختبار

- React production build، Vitest، وتجربة الواجهة داخل Chromium: **غير متحققين** في هذه الجولة بسبب عدم وجود حزم React مثبتة في بيئة الاختبار.
- Gemini Live باستخدام مفتاح حقيقي: **غير منفذ**.
- اختبارات ضغط موزعة بأعداد مستخدمين حقيقية أو معدلات أداء إنتاجية: **غير منفذة**.
- فحص اختراق شامل / SAST-SCA متقدم / تدقيق حزم npm على الإنترنت: **غير منفذ**.
- استضافة عامة، PostgreSQL، أو استعادة Backup في بيئة الإنتاج: **غير منفذة**.

لا يجوز الاستنتاج من نجاح تلك الاختبارات أن الموقع جاهز للإطلاق التجاري.

## إعادة الاختبار

من جذر المشروع بعد تثبيت متطلبات Backend (بما فيها `requests` و`uvicorn`):

```bash
python scripts/qa_adversarial_extra.py
```

ستجد تقرير التنفيذ الآلي بصيغة JSON في:

`qa_reports/qa_adversarial_extra_2026-10-17.json`

لا يتصل السكربت بأي Gemini/OpenAI؛ يشغل خادمًا محليًا وقواعد بيانات تجريبية في مجلد مؤقت، ثم يغلقه تلقائيًا.
